# astrbot_plugin_wows_asia

[AstrBot](https://github.com/AstrBotDevs/AstrBot) 战舰世界（WoWS）**亚服**战绩查询插件：图片战绩卡、单船战绩、最近战绩（逐场记录）、账号绑定，并提供给大模型调用的函数工具。

由 [nonebot-plugin-wows-asia](https://github.com/Danyuyuyuyu/nonebot-plugin-wows-asia) 移植而来，现在独立维护：大模型调用改成了结构化参数，不再和 NoneBot 版同步。

- 只使用 WG 公开 API（`https://api.worldofwarships.asia/wows/`），只需要 `application_id`，不需要玩家密码或 OAuth。
- 卡片为本地 HTML 模板 + 无头 Chromium 截图，不加载外部网络资源；渲染失败时自动降级为文字。
- 适用于 AstrBot 支持发送图片的平台（QQ 个人号 aiocqhttp、QQ 官方、Telegram、Discord 等）；`@群友` 查询需要平台支持 @。

## 安装

1. AstrBot 管理面板 → 插件 → 安装插件，填仓库地址 `https://github.com/Danyuyuyuyu/astrbot_plugin_wows_asia`（或上传本仓库的 zip）。依赖（httpx、playwright、pypinyin）会按 `requirements.txt` 自动安装。
2. 在**运行 AstrBot 的同一个 Python 环境**里安装截图用的 Chromium（只需一次）：

   ```bash
   python -m playwright install chromium
   # Linux 服务器缺系统库时：python -m playwright install --with-deps chromium
   ```

   用 uv / 一键包启动的 AstrBot，请用它自带的 Python 执行上面的命令。已有 Chrome/Chromium 的话，也可以在配置里填“浏览器路径”跳过这一步。
3. 服务器需要中文字体，否则卡片中文会显示成方块。Debian/Ubuntu：`apt install fonts-noto-cjk`；CentOS/RHEL：`yum install google-noto-sans-cjk-ttc-fonts`。
4. 在插件配置里填写 `application_id`（见下），保存后插件会自动重载。

不想装浏览器时把“输出方式”改为 `text`，所有功能以文字回复。

## 配置

先在 [WG 开发者中心](https://developers.wargaming.net/) 用亚服账号创建应用获取 `application_id`（选 Server 类型），然后在 AstrBot 管理面板 → 插件 → WoWS 亚服战绩 → 配置中填写：

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `application_id` | 空 | **必填**。未填写时插件可加载，但查询会提示管理员配置，战绩记录不启动 |
| `render_mode` | `image` | `image` 图片卡片 / `text` 纯文字 |
| `render_scale` | `1.5` | 截图倍率（1–3），越大越清晰、图片越大 |
| `browser_path` | 空 | 使用系统已有 Chromium/Chrome 的可执行文件路径 |
| `ai_reply` | `点评` | 大模型调用后：`点评`（发卡片并让模型点评）/ `只发卡片` |
| `tool_on_demand` | 开 | 只在和战绩相关的对话里提供函数工具 |
| `tool_keywords` | 空 | 按需提供时额外识别的词，空格或逗号分隔 |
| `timeout_seconds` | `15` | 单次 API 请求超时 |
| `cache_seconds` | `60` | 账号数据缓存时间 |
| `poll_minutes` | `10` | 快照检查间隔（3–720 分钟） |
| `fast_poll_minutes` | `3` | 已绑定 / 最近在打的账号的检查间隔（0–60 分钟；0 或不小于上一项时关闭） |
| `track_days` | `14` | 未绑定账号多少天无人查询后停止记录 |
| `max_tracked` | `200` | 最多同时记录的账号数（绑定账号不受限） |
| `record_days` | `30` | 逐场记录保留天数（≥15） |
| `min_battles` | `50` | 随机场次低于此值显示新号状态卡 |
| `ship_names_path` | 空 | 可选，客户端船名文件（`zh_sg.json`）路径，用来显示与游戏客户端一致的船名；默认 `data/wows_ship/names/zh_sg.json`，不存在时使用 API 船名 |

数据（绑定、快照、记录）保存在 `data/plugin_data/astrbot_plugin_wows_asia/wows_asia.sqlite3`，更新或重装插件不会丢失。

## 指令

前缀以 AstrBot 的唤醒词为准（默认 `/`）；群聊里也可以 @机器人 后发送。

| 指令 | 说明 |
| --- | --- |
| `/wows 玩家昵称` | 总战绩卡（随机战斗生涯；写成 `/wows 生涯 昵称`、`/wows 昵称 总战绩` 也行） |
| `/wows id 账号ID` | 按账号 ID 查询（纯数字昵称仍按昵称处理） |
| `/wows 绑定 昵称`（或 `绑定 id 账号ID`） | 绑定自己的账号，并立即开始记录快照 |
| `/wows` / `/wows 我` | 查自己的总战绩（需先绑定） |
| `/wows 最近 [昵称]` | 最近 7 天汇总 + 每日战况 + 最近两天逐场列表 |
| `/wows 场次 [谁] [筛选]` | 按条件列出记录到的场次（汇总 + 逐场） |
| `/wows 单场 [谁] [筛选/序号]` | 单场详情（按筛选和排序取第 1 场；默认最近一场；`单场 3` = 第 3 场） |
| `/wows 单船 船名 [谁]`（或 `战舰 船名 [谁]`） | 某艘船的生涯数据（直接读 WG 战舰统计，不需要先记录；船名写在第一个，支持错字/同音字；加 `排位` 看排位数据；`/wows 张三 船=大和` 同样可用） |
| `/wows 解绑` | 取消绑定 |
| `/wows 帮助` | 帮助 |

**谁**：`我`（默认）、昵称、`id 账号ID`、`@群友`（查对方绑定的账号）。

**筛选**（空格分隔、顺序随意）：

| 类别 | 写法 |
| --- | --- |
| 时间 | `今天` `昨天` `前天` `近3天` `本周` `10-15` `10-12~10-15`（不写时：场次默认近 7 天；单场、指定船或排序时为全部记录） |
| 时段 | `凌晨`(0–6点) `上午`(6–12) `中午`(11–13) `下午`(12–18) `傍晚`(17–19) `晚上`(18–24)，可和日期连写如 `今天下午` `昨天晚上`；也可写 `14点后` `9点前` `14-18点`。只写时段时默认今天。按记录到的快照时间算，可能比实际结束晚几分钟 |
| 战舰 | `船=大和`（按名字包含匹配，只在打过的船里找）。打错字或同音字会自动纠正，如 `船=大合` → 大和、`船=衣吹` → 伊吹，卡片上会注明“由‘大合’纠正”；拿不准时回复“是不是想查：A / B / C”；完全对不上时列出最近打过的船 |
| 模式 | `随机` `排位` `单野` `组队` `双排` `三排` |
| 结果 | `胜` `负` |
| 排序 | `按伤害` `按击沉` `按经验` `按侦察` `按潜在`（也可写 `伤害最高`）为从高到低；`伤害最低` `击沉最少` `最低经验` 等为从低到高；不写按时间倒序。数值相同时再按伤害比 |
| 好坏 | `最好` `最差`（按经验从高到低 / 从低到高；可带数量：`最好5把` `最差的3把`）。经验综合了伤害、击沉、占点、点亮等，不同舰种之间也能比 |
| 数量 | `前5` |

例：`/wows 场次 张三 今天下午 船=伊吹`、`/wows 单场 今天 按伤害`、`/wows 场次 昨天 船=大和`、`/wows 场次 @张三 近3天 排位`、`/wows 场次 近3天 最差5把`、`/wows 单场 今天 伤害最低`。

别名 `/窝窝战绩`。昵称精确匹配失败时最多返回 5 个候选，不会擅自使用第一个候选。

## 大模型函数调用

插件注册了函数工具 **`wows_query`**（可在管理面板 → 函数工具 中启用/停用）。模型不需要拼指令，而是按字段填参数，插件逐项校验后直接执行：

| 参数 | 写法 |
| --- | --- |
| `action`（必填） | 总战绩 / 最近 / 场次 / 单场 / 单船 / 绑定 / 解绑 |
| `player` / `account_id` / `mention_id` | 其他玩家昵称 / 账号 ID / 被@群友的 ID（消息里 `@昵称(ID)` 括号中的数字，看不到时填 `@`）；都不填 = 提问者本人 |
| `ship` | 船名（错字、同音字自动纠正） |
| `date` | 今天 / 昨天 / 前天 / 近N天 / 本周 / 10-15 / 10-12~10-15 / 今天下午 |
| `start_hour` / `end_hour` | 时段，如下午 = 12、18 |
| `mode` / `result` | 随机 / 排位 / 单野 / 组队 / 双排 / 三排；胜 / 负 |
| `sort` / `order` | 时间 / 伤害 / 击沉 / 经验 / 侦察 / 潜在；从高到低 / 从低到高 / 从新到旧 / 从旧到新 |
| `limit` / `nth` | 场次取排序后前几场（默认最新的）；单场取第几把 |

例：“张三三的大和打得怎么样” → `{"action": "单船", "player": "张三三", "ship": "大和"}`；“我近 3 天最差的 5 把” → `{"action": "场次", "date": "近3天", "sort": "经验", "order": "从低到高", "limit": 5}`；“我记录到的最早一把” → `{"action": "单场", "order": "从旧到新"}`。

- **结果**：查到卡片时插件直接把图片发到聊天里，工具返回 JSON：`status`（ok / not_bound / candidates / noship / nomatch / tracking / hidden / error / invalid 等）、卡片上的数据（数字精确，模型不能识图也没关系）、`options`（候选昵称或建议船名）和 `next`（这种情况下该怎么做，例如候选昵称要先问用户、建议船名可以直接重查一次）。参数填错时返回 `invalid` 和改法，不会猜一个结果去查；被忽略的参数写在 `notes` 里。
- **回复方式**（配置“大模型调用后的回复方式”）：默认发卡片后让模型简短点评；选“只发卡片”时卡片发出即结束这一轮，少调用一次模型，但模型拿不到数据，之后追问具体数字答不上来。
- **按需提供**（配置“按需提供函数工具”，默认开）：只有消息看起来和窝窝战绩有关（战绩、船、场次、伤害、打得怎么样、查过的船名等），或同一会话 10 分钟内刚用过时，才把工具交给模型，闲聊时不占 token。常用问法识别不到时，在“额外关键词”里补充或关闭此项。
- 对比多人（“我和张三三谁胜率高”）时模型会分别调用。
- 需要使用支持函数调用的模型，并在当前会话启用工具调用。

## 卡片内容

**总战绩卡**（除“随机 vs 排位”的排位列外，全部为随机战斗数据，卡片各区块均有“随机战斗”标签）：随机胜率环图（胜/负/平）、场数、场均伤害/击沉/经验、存活率、主炮命中率；舰种表现（使用占比 + 胜率条，0–100% 刻度）；等级分布（I–X 级各级场数柱状图 + 各级胜率，有超级战舰时显示 XI）；随机 vs 排位对比；单野/双排/三排胜率；单场最高伤害/击沉/经验/侦察及对应战舰。

**最近战绩卡**：近 7 天汇总（对比生涯）；按天的胜负堆叠柱；最近两天的逐场列表（时间、胜负、战舰、舰种/等级/模式、伤害及与本船生涯场均的对比、击沉、经验、存活）。

**场次卡**：筛选结果的胜率环图与场均数据（只有一艘船时对比该船生涯，否则对比随机生涯）；不排序时按天分组，排序时平铺并显示日期。

**单船战绩卡**：本船胜率环图、场数（占 TA 随机多少）、场均伤害/击沉/经验、存活率、主炮命中率（对比 TA 全部随机战斗场均）；场均侦察/潜在伤害、点亮、鱼雷命中率、击落飞机、占点/防点；本船 vs TA 其他同等级同舰种的船合计 vs 本船排位（或随机）对比表；本船单野/双排/三排胜率；本船单场最高伤害/击沉/经验；常用排名（TA 第几常用的船）；已有记录时附本船近期每场伤害柱状图。船名被纠正或同时匹配多艘时卡片会注明（多艘时优先完全同名，否则取场数最多的）；TA 没开过这艘船时提示相近船名或 TA 最常开的船。

**单场详情卡**：胜负、战舰、模式与单野/组队、存活；伤害、击沉、经验、侦察伤害、潜在伤害、点亮、主炮/鱼雷命中率、击落飞机（均对比本船生涯场均）；主炮/鱼雷/副炮击沉、副炮命中率、占点/防点；本船新纪录标记（伤害/击沉/经验）；本船近 10 场伤害柱状图与排名。0.2.7 之前记录的场次只有基础数据。标题注明是第几场（如“最新一场 · 按时间第 2 / 共 2 场”）；条件下有多场时提示改用“场次”查看全部。

**军团颜色**：军团标签使用游戏内的军团颜色（按军团战段位：飓风紫、台风绿、风暴金、疾风银、暴风古铜，未参加军团战为灰色），并在账号行显示军团全名与段位（如“暴风 III”），未加入军团显示“无军团”。颜色和段位来自 WG 官方军团站 `clans.worldofwarships.asia` 的公开接口（非开发者文档接口，无需 application_id，每个军团缓存 1 小时）；查询失败时显示灰色，不影响出卡。

卡片不显示头像：WG 公开 API 不提供玩家游戏内头像。舰种表现和等级分布不含战舰图鉴中查不到的船（已删除/下架的老船等），其场次仍计入总场数和胜率。

**状态卡**：隐藏战绩、刚开始记录 / 近 7 天无战斗、追踪名额已满、随机场次少于 `min_battles`（默认 50）的新号。

## 最近战绩的原理与限制

WG 公开 API **没有逐场战斗记录接口**。插件定时保存每艘船的累计数据快照，两次快照之间的差值就是这段时间打的战斗：

- 只能记录**开始记录之后**的战斗。绑定账号或第一次查询 `/wows 最近 某人` 时开始记录，之前的场次查不到。
- 定时任务先批量检查 `last_battle_time`，有变化才拉取战舰数据，请求量很小。**已绑定、还没建立基线或 2 小时内打过战斗**的账号每 `fast_poll_minutes`（默认 3）分钟检查一次，其余账号每 `poll_minutes`（默认 10）分钟一次。一局最长约 20 分钟，3 分钟间隔下两次快照之间基本只有一场，差值就是准确的单场数据。
- 同一艘船在两次快照之间打了多场时只能合并成一行显示（灰底，数值为场均）。显示的时间是快照时间，可能比实际结束晚几分钟。
- 随机战斗会标注**单野 / 双排 / 三排**（对比每船 `pvp_solo` / `pvp_div2` / `pvp_div3` 场数的差值得到）；合并行显示各自场数，如“单野1 双排1”。升级到 0.2.6 之前记录的场次没有这项信息。
- 记录随机（pvp）和单人排位（rank_solo）；行动、剧情等模式不计入。
- 防重复计数：同一账号的刷新串行执行（用户查询碰上定时检查会等它完成，不会重复请求）；WG 偶尔返回的旧数据（场数比已存快照少）会被忽略，快照不会回退；每条记录带该船结束时的累计场数并建唯一索引，同一段场数只会写入一次。
- 绑定账号会一直记录；未绑定账号在 `track_days` 天内没人查询就停止记录；逐场记录保留 `record_days` 天。

## 从 NoneBot 版迁移

AstrBot 版的数据库和 NoneBot 版结构相同，只是用户标识不同（NoneBot：`OneBot V11:QQ号`；AstrBot aiocqhttp：`aiocqhttp:QQ号`）。不迁移的话，大家重新 `/wows 绑定 昵称` 即可，但之前记录的逐场战绩会查不到。

要保留绑定和记录：先在 AstrBot 里安装并启动一次本插件，然后**停止 AstrBot**，在 AstrBot 根目录执行：

```bash
python data/plugins/astrbot_plugin_wows_asia/scripts/migrate_from_nonebot.py 旧的/wows_asia.sqlite3 --force
```

旧数据库一般在 NoneBot（真寻）的 localstore 数据目录下，文件名 `wows_asia.sqlite3`（可用 `find / -name wows_asia.sqlite3` 查找）。`--force` 会用旧数据覆盖 AstrBot 版已有的数据。脚本只读取旧库，不会修改它。

## 说明

- 统计以随机战斗 `statistics.pvp` 为主；排位为 `rank_solo`；组队为 `pvp_solo/pvp_div2/pvp_div3`。缺失数据显示为 `—`。
- 不计算 PR 评分（需要第三方期望值数据）。时间统一按 UTC+8 显示。
- 错误提示不会包含 application_id 或请求 URL。
- 卡片配色借鉴《别当欧尼酱了！》绪山真寻的樱粉 + 薰衣草紫，不含任何官方立绘或素材。

## 开发

```bash
pip install -e /path/to/AstrBot pytest pytest-asyncio
pip install -r requirements.txt
pytest
```

`wows/` 是不依赖 AstrBot 的核心（查询、记录、卡片、函数工具参数解析），`main.py` 负责接入 AstrBot。
